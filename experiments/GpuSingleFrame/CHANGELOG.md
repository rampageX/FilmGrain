# GPU 单帧实验版变更记录

## R12（2026-11-08，Windows / RTX 4080 待验证）

- R11 用户实测：初次 Grain Plate 抽帧 3161 ms，切帧 3689–4544 ms；移到 NVMe 无明显改善，抽帧时 CPU 100%、GPU 接近空闲。两份素材分别为网上下载和 FGG 生成，但均是约 10 秒、240 帧的 4K ProRes HQ、YUV422P10，编码格式一致。
- 仅对 FFprobe 确认的**短时、恒定帧率、10-bit 4:2:2 ProRes**启用快速循环定位：由帧数和帧率计算 FFmpeg 近似循环周期 `(帧数 - 1) / 帧率`，对视频时间求余，再执行原 `-stream_loop -1 -ss`。避免为 65 秒等长时间点重复遍历之前的 ProRes 循环。FFprobe 缺失、非 ProRes 或元数据不可信时完整保留 R11 原抽帧命令。启动和独立窗口切帧采用相同周期；正式编码路径及实时 GPU Overlay 完全不动。
- Linux FFmpeg 6.1.1 合成 ProRes 实测：65.6 秒抽帧从约 0.59 秒降至约 0.10 秒（640×360 输入、缩放至 1920×1080），**只是优化方向验证，不代表 4080 上 4K 素材实测**。循环帧相位可能受 FFmpeg 时间戳舍入影响，尚未确认与原路线逐帧哈希相同；需检查实际动态观感与正式成品。
- 清理 R9 以来 libplacebo `pl_plane_data_from_comps` 的两处 `const int[]` 编译警告，改为接口要求的可写 `int[]`，数值不变。

## R11（2026-11-08，Windows / RTX 4080 待验证）

- 修复 R10 已确认的选帧等待问题：首次进入高级预览时，FGS 后台并行启动主视频和 Grain Plate 两路 FFmpeg；独立 GPU 窗口内切时间点时，先启动两个 FFmpeg 子进程，再等待结果，两路均成功才更新纹理。原始解码参数、选帧时间、Overlay Shader、颗粒/LUT 滑块和正式编码核心不变。
- 新增选帧耗时记录：首次抽帧按视频/颗粒/并行总耗时记录；窗口内每次切换打印 `FRAME_DECODE,video_ms,plate_ms,total_ms`。关闭 GPU 窗口后 FGS 日志汇总显示；两路各自耗时不因等待另一进程而失真。
- 这是针对双 FFmpeg 串行等待的延迟优化，**不保证缩短固定比例**；同盘双路解码可能争用 IO，实际收益以用户 Windows / RTX 4080 实测为准。

## R10（2026-11-08，Windows / RTX 4080 用户已验收）

- 为 HEVC/H.264/x264 的扫描 Grain Plate（及 SVT-AV1 像素扫描颗粒）接入真实 GPU 实时路径：主视频与循环 Grain Plate 仅在初次进入和手动选帧时通过 FFmpeg 抽为 `yuv420p10le`，各自上传三张 D3D11 GPU 纹理；滑动时使用 libplacebo `PL_HOOK_NATIVE` 的自定义 Overlay Shader 和动态混合系数，**不启动 FFmpeg、不重复上传帧**。
- 对照正式编码 `blend_vulkan=all_mode=overlay:all_opacity=…` 的 top/bottom 顺序；libplacebo 已规范化的源 YUV 与直接采样 R16 的 Plate 分别处理，后者乘 64；新增纯 C Overlay 数学测试并用 FFmpeg CPU `blend` 参考值交叉检验。
- 强度遵循原 FGS Grain Plate 的 15–100% / 5% 档位；独立 JSON v2 单独回传 `PixelMode=PLATE` 和 `PlateStrength`，不复用或篡改 AV1 的 1% 强度控制。0% 仅表示关闭；`G` 开关保留。选择新时间点会同步重新抽取颗粒视频帧。
- 保留 R9a 的初始随机帧、1:1/选帧、窗口记忆、LUT、AV1 预设及正式编码不变。Digital Grain、FGSIM、ISO 实时生成和 HDR 本轮未改。**用户 RTX 4080 反馈强度变化明显、拖动流畅、1:1 正常、回传及实际编码正确，动态效果与预览非常接近**。初次打开和手动选帧耗时约 2–3 秒，作为 R11 优化目标。

## R9a（2026-11-08，Windows / RTX 4080 待验证）

- 打开高级 GPU 预览时改为随机选取初始视频帧，复用已验证的普通颗粒预览随机选点规则，不再把超过 25 秒的视频固定在第 15 秒。视频短于 1 秒时安全回退到第 0 秒。
- 仅改 .NET 调用层初始时间选择，原有 GPU 渲染、编码与颗粒强度计算均不变。

## R9（2026-11-08，Windows / RTX 4080 待验证）

- 底部时间输入框移至“随机一帧”“跳转”前方；按 Segoe UI 9pt 实际时间码宽高计算紧凑尺寸，三控件底边对齐。绘制、点击命中及窗口缩放使用同一组坐标。
- 独立 GPU 预览窗口在当前用户注册表保存普通窗口的位置和大小、最大化状态，重开恢复；若显示器已断开或原窗口不在可用工作区，则使用安全的默认位置。
- 仅更新实验预览的 Win32 UI 和编译链接选项；R8 已通过用户的 MaxMid 颗粒视觉验收。正式编码及 FGS 旧预览不变。

## R8（2026-11-08，Windows / RTX 4080 用户已验收）

- 修复 Film Preset / Grain Table 的 GPU 预览颗粒几乎不可见：原型将 `filmgrn1` 的 `seed=0` 直接交给 libplacebo，使 AV1 亮度颗粒随机数生成器卡在零状态；正式编码的 grav1synth 会为选中的事件逐帧将种子加 `10956`（16-bit 回绕）。
- 新增每事件起点记录和纯 C 帧种子计算函数；依实际选择的时间点、事件起点和标称帧率推进种子。切帧后重新计算；强度／LUT 滑动时复用同一帧种子。
- 新增可选 CLI 参数 `--fps NUM/DEN`（也接受小数）；FGS 自动从已探测的 `avg_frame_rate` 传入。旧 CLI 默认 30fps 估算；VFR 或实际编码帧率变更不保证与成品颗粒逐像素一致。
- Linux GCC 测试通过 14 套 Film Preset 事件及新增种子回绕、事件重置、分数帧率、MaxMid 65.588 秒案例；正式编码核心、原有预览、GUI 1% 参数回传及 LUT 未修改。
- 顺带静态核对 FGS ISO 正式编码仍传入 `grav1synth --iso`；现有 1080p Photon Noise ISO1600 参考表的亮度点值只有 1–7，明显弱于 MaxMid。ISO 成品仍需用户素材验证，当前不调整算法。

## R7（2026-11-08，Windows / RTX 4080 待验证）

- 视频画面双击切换「1:1 原始预览帧像素／适应窗口」，1:1 状态支持鼠标拖动查看其他区域，快捷键 `1` 同样切换。
- 新增第三条视频时间轴、时间输入框、跳转按钮和随机一帧；松开时间轴才执行 FFmpeg 抽帧并刷新 GPU 纹理。切帧同步更新多事件 Grain Table 的时间点模型。
- FGS 独立调用增加原视频路径、FFmpeg 路径与视频时长参数；双击 1:1 不需要重新解码，颗粒和 LUT 调整依旧保留既有 GPU 热路径。
- 1:1 使用原始偶数分辨率输入抽帧（不再固定最高 1920）；4K 显存／性能增量尚需实机验证。
- 控件文字统一 Segoe UI 9pt（与 FGS 主界面一致），滑块标题右对齐紧邻轨道，新增控件按三行滑杆与底部操作行对齐。

- 滑块标签、百分比与“应用到 FGS / 取消”按钮统一使用 Windows 微软雅黑 UI 字体，并与轨道／按钮垂直居中。

## R5（2026-11-08，Windows / RTX 4080 用户已验证）

- FGS 主界面在颗粒和 LUT 中间新增“高级预览调整…”按钮；FFmpeg 只抽一帧后启动独立 GPU 程序，不更改既有预览或编码路线。
- 原型新增 `--result` 及初始值/开关参数；底部“应用到 FGS”与“取消”，只有显式应用才回传 JSON。支持未开启颗粒时的 LUT-only 预览。
- FGS 主界面 LUT 滑块与调色窗口调整为 0–100% / 1%，AV1、HEVC、H.264 编码入口同步接受任意整数强度。
- 预设新增 v2 的 0–100 百分比格式；读入既有 v1 预设时将旧 0..4 档位换算成 0/25/50/75/100，仅更新内存副本，旧文件不自动改写。
- 保留 FGS 颗粒主滑块的 5% 精度；回传时舍入并记录，避免 silently 保存预览的细档。
- 本次为 f2ab7dd 基线的未发布测试修改；首次 Windows C# 构建遇到 CS0160，移除重复捕获异常后用户确认所支持的 AV1 模式工作正常。

## R4（2026-11-08，用户已验证）

- 新增暗色双鼠标滑块：颗粒、LUT 0–100%，各 1% 步进；点击及拖动都立即重绘。
- GPU 视频改为独立 D3D11 子 HWND，和下方 GDI 滑块区域分开，避免相互覆盖导致闪烁；仍保留所有旧键盘操作。
- 1% LUT 使用单份可重用 CPU LUT 缓冲区，并通过 libplacebo 签名触发 GPU LUT 更新，视频 YUV 三平面纹理不重复上传；原有 25% 预计算档位保留。
- 增加 `LUT_BENCH_*` 性能统计；用户测得颗粒均值 4.545 ms、LUT 均值 3.966 ms、LUT P95 6.069 ms；实时调整顺滑、无闪烁。
- 静态检查补充《沙丘2》原始表及 MOD_E3 表，各 1,868 个事件。
- R4 本身无 FGS Stable、WinForms 或发布流程改动。
